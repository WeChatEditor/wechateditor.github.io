# 轻量传稿插件安装与验收

当前版本0.1.13，协议2，Chrome桌面最低120。支持维护者提供的首页weui-desktop_name及其他页面acount_box-nickname。自动保存同步最新文字排版供插件复制，手动发送才尝试自动插入；完整公众号流程仍待人类验收，构建和接收应答不证明插入或保存成功。

0.1.13工具栏图标随当前标签切换：桀士排版站点和公众号后台显示蓝色，其他网页及Chrome内部页显示灰色。匹配精确origin，不依赖网页标题；蓝色只表示位于支持站点，灰色仍可打开面板。切换标签、导航/返回/刷新和浏览器启动自动更新，各窗口/标签互不覆盖。开发包另支持127.0.0.1:5175/4175。无需新增权限，真实显示和切换由维护者验收。

0.1.12新增面向用户的manifest摘要和公开插件主页，未改ID/权限/传稿行为。网站发布后安装帮助为https://wechateditor.github.io/extension/，隐私说明为https://wechateditor.github.io/privacy/；商店字段和发布文案见[参考](../reference/chrome-web-store-listing.md)。

## 安装与更新

1. 执行pnpm package:extension，得到apps/extension/dist/production及apps/extension/dist/jlab-wechat-transfer-0.1.13.zip。
2. Chrome打开chrome://extensions，打开开发者模式，加载production目录或解压后的ZIP目录。插件稳定ID与extension.identity.json一致，可固定到工具栏。
3. 已安装旧版时在扩展管理页重新加载，再刷新Web和公众号标签。协议仍为2，连接检测需0.1.6、自动同步需0.1.5；旧0.1.4保留的快照兼容迁移，旧v1快照不执行，0.1.3已清除正文无法恢复。更新后修改正文或排版并等待保存，或者手动发送，即可在插件复制。
4. 生产Web为[组织站点](https://wechateditor.github.io/)。本轮仅本地修改/打包，线上更新需另行推送部署。
5. 本地验收运行pnpm dev:frontend、pnpm build:extension:dev，加载apps/extension/dist/development，访问http://127.0.0.1:5175/（preview为4175）。开发/生产包相同ID，只安装一份，插件不搬迁不同origin的Web数据。

权限仍仅storage/scripting及公众号、组织Web两个host，无cookies/debugger/全局tabs。logo.png只向公众号页面开放以显示后台浮层。卸载扩展删除插件本地快照，但不影响Web原稿或后台已创建内容；重装后需重新发送。

本次另准备apps/extension/dist/jlab-wechat-transfer-0.1.13-store.zip供商店上传，只从已校验本地ZIP移除manifest.key；其余资源保持一致，常规package:extension仍生成原稳定ID本地包。商店草稿生成ID后需核对并对齐Web连接及本地开发身份，上传成功不能代替连接或功能验收。本次没有执行上传、审核或发布。

## 使用

打开Web会检测插件：未安装/禁用/版本不兼容时右侧为蓝色“复制到公众号”，左侧发送图标悬停可看提示；安装0.1.13并允许当前站点访问后，刷新Web或在发送抽屉点击“重新检测”，右侧切为蓝色“发送到公众号”，左侧为复制图标。点击发送会同时复制当前排版，抽屉分别显示复制和插件接收结果；没装插件也会提示安装，复制仍可用。剪贴板权限失败不会取消插件发送。

发送抽屉的“打开传稿面板”仅在插件连接可用时启用；缺失时查看安装说明。公众号右下浮层可拖动标题栏，也可聚焦标题后用方向键移动、Shift加速、Home恢复位置；缩放后保持在视口内。导航文字可换行，长标题和提示不会顶出边界。收起后点“桀士传稿”可恢复。已打开网页的插件失效时，下一次打开面板失败会禁用入口并提示启用插件及刷新；未安装插件的新公众号页不会注入浮层。

日常写作无需点击发送：正文/标注/素材在本机自动保存成功后，排版/固定头尾配置保存成功后450ms防抖，同步当前文字排版到插件。保存状态显示“插件已同步”，悬停可查看同步结果；只改变排版也会更新。自动同步不打开后台、不创建任务、不写系统剪贴板。打开插件面板点击“复制到公众号”或“复制标题”，再到公众号粘贴并手动保存。系统剪贴板在点击复制或发送时变化。

本机保存与插件同步分别成功：无插件、图片/空正文/标题超限/2MiB保护、权限或存储失败时，本机草稿继续保存，状态悬停说明“插件未同步，已有快照未更新”。修复后修改一次或点击发送重新保存快照。冲突/恢复/页面卸载不发出新的同步；关闭页面补保存是尽力操作，不保证插件同步完成。初始化仅恢复本机数据，不主动传入示例稿。

需要自动新建插入时，继续使用手动发送：

1. 在Web完成文字排版，直接点击“发送到公众号”。自动提取正文H1为标题，缺失则使用“未命名文章”，不再另填标题或确认任务。
2. 当前内容交给插件后打开独立后台，使用已选有效公众号或第一个可用账号，依次点击左侧“草稿箱”、“新的创作”、“文章”。文章入口优先，兼容旧图文名称；保留平台打开新标签的行为，只向本次文章操作打开的唯一新空编辑器插入当前发送快照。
3. 没有可用后台标签时先打开固定公众号首页；已有登录状态会自动识别账号并继续，未登录则等待用户登录。登录标签完成加载后继续识别，账号延迟出现时最多探测30秒；未识别时可打开插件点击公众号下拉右侧刷新图标继续未启动任务。可提前选择公众号，后续发送优先使用该选择。
4. 在平台新开的文章编辑标签中核对标题、正文、头尾和排版，补充封面/摘要等信息，手动保存并重开确认。自动执行期间请等待，操作正文或后台页面会中止本次自动插入。
5. 如自动插入未完成，直接点击工具栏插件图标，在面板点击“复制到公众号”，到公众号正文编辑区粘贴；可用“复制标题”填标题栏。复制保留最新成功自动保存或手动发送的排版，不需返回编辑器。成功、失败及worker中断后均可复制，不检查发送状态，也不重新触发插入。

没有确认checkbox、手动启动、取消或恢复清理按钮，没有发送状态检测/轮询。面板在打开/刷新/选择时读取账号与页面能力，后台执行另有登录页就绪与导航能力检查；浮层收到一次性插入成功或失败提示。Chrome无法自动打开popup时会打开本地面板标签，也可点击工具栏图标。

接收后Web修改不会改变已发送任务，自动保存只更新插件可复制快照。可复制快照保留至24小时到期或成功同步/再次发送替换，复制不会删除它。再次点击发送更新任务和可复制快照，正在执行时提示稍后发送；执行期间自动保存可正常更新复制内容。中断不会自动重放；如再次发送，应先查看后台是否已创建/插入内容。标题超过64个Unicode字符时需调整正文H1；含图片整篇使用编辑器既有“复制到公众号”，图片传稿范围没有扩大。

## 失败处理

- 标题覆盖层：0.1.11识别实际可见ProseMirror标题，使用浏览器原生编辑事务并核对隐藏旧textarea同步。标题控件尚未就绪最多等待原30秒；正文或标题真实非空仍停止。标题同步失败显示具体原因，检查平台页面后使用插件复制退路，不自动重试。

- 新文章页无插入：0.1.10支持编辑器隐藏账号名称，只在本次新增文章子标签核对唯一隐藏名称与原目标账号严格一致后继续。接口需就绪且标题/正文为空；账号空值、多候选或不一致仍停止。重新加载插件并刷新页面后复验标题/正文、排版与手动保存。

- 创作菜单：0.1.9读取“文章”的可见名称标签，忽略同名隐藏tooltip。若旧版在菜单已显示时仍报未找到“文章”，重新加载0.1.9插件并刷新公众号页面后再发送，复验平台新开的文章标签及正文插入。

- 首页菜单：0.1.8按左侧“内容管理”内的链接定位草稿箱；折叠时先点击一次内容管理并等待。正文里的同名按钮不会干扰。若菜单/入口未加载，等待最多30秒后显示具体原因；多个可见入口或禁用会停止，不任取第一个。

- 无插件/权限/版本不兼容：检查安装及站点访问权限，两端同时更新，复制流程仍可用。
- 没有账号：登录后台首页或草稿箱再刷新；已有编辑页不作为自动新建起点。
- 接收超时：查看后台是否已产生内容，插件没有自动重试。
- 非空编辑器、账号变化、入口/JSAPI缺失或超时：停止自动写入，检查后台一次性提示，必要时使用复制。
- 插件更新/浏览器中断：不自动重放旧执行，0.1.4接收的快照仍可直接从面板复制。
- 复制失败：保持插件面板打开并再次点击，检查桌面Chrome剪贴板权限；缺失/到期内容需在Web重新发送，不静默降级为纯文本。
- 存储格式无法识别：Web原稿保留，重新安装插件后发送。
- 24小时到期：快照/回执在读取或命令时删除，重新发送当前内容。
