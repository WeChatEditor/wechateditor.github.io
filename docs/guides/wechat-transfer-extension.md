# 轻量传稿插件安装与验收

当前版本0.1.0，Chrome桌面最低120，稳定ID `imiclghaaoleoggfhfdbanmaehamnpmg`。真实公众号尚未验收；入口/账号/标题定位是保守候选，页面不支持时显示原因并停止。插件只新建并插入文字排版，最后由用户检查并手动保存。

## 安装与更新

1. 构建：根目录执行`pnpm package:extension`，得到`apps/extension/dist/production`及`apps/extension/dist/jlab-wechat-transfer-0.1.0.zip`。ZIP解压后同样可加载。
2. 在Chrome打开`chrome://extensions`，打开开发者模式，选择“加载已解压的扩展程序”，选中包含manifest.json的production目录；核对上述ID。将插件固定到工具栏。
3. 生产Web为[组织站点](https://wechateditor.github.io/)。本次Web代码尚未推送或部署，线上旧版不会立即出现发送入口；部署Web与安装插件是两步。原复制始终可独立使用。
4. 本地验收：执行`pnpm dev:frontend`和`pnpm build:extension:dev`，加载`apps/extension/dist/development`，打开`http://127.0.0.1:5175/`。preview使用4175。开发/生产包相同ID，只安装一份；切换前先处理待传任务。插件不搬迁不同Web origin的数据。
5. 更新代码后重新构建，在扩展管理页点击“重新加载”，再刷新Web和公众号标签。任务结构未知或执行被打断时先检查后台，通过面板明确丢弃，不自动重试。

卸载：先检查后台并处理待传任务，再在扩展管理页“移除”。扩展本地任务随卸载清除，Web原稿和公众号已创建内容由各自页面保留。重新安装需重新发送快照。

生产权限只storage/scripting和公众号、组织Web两个host；无cookies、debugger、全局tabs或剪贴板权限。生产不含本地来源。修改Web域名必须一起调整契约来源和构建manifest，不把任意站点加入白名单。公开key用于稳定ID，仓库不含私钥或公众号凭据。

## 使用

1. 在Web完成文字排版。含正文或启用头尾图片时使用“复制到公众号”。
2. 点击“发送到公众号”，确认临时标题，点击“发送并打开公众号”。标题不会写回原稿，正文H1也保留。
3. 在公众号登录后打开后台首页或草稿箱。点击工具栏插件图标，刷新目标与页面能力。多个标签必须明确选择；编辑页不能作为起点。
4. 核对所选账号，勾选确认，点击“新建图文并插入”。插件打开独立后台标签，不离开原编辑页。执行期间等待，暂不切换或编辑后台页面。
5. 看到“已插入，请检查排版并手动保存”后，核对标题、正文、头尾和样式，补充封面/摘要等后台必要信息，手动保存，再重开确认内容。

公众号浮层的“打开传稿面板”在Chrome策略不允许openPopup时会提示使用工具栏图标。收起浮层不取消任务。单个待传任务不会跟随Web后续改稿；重送需要明确替换尚未执行的旧快照。

## 恢复

| 状态             | 操作                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 插件未连接       | 检查安装、ID、站点访问权限、Web地址和两端版本；使用复制退路                               |
| 接收应答丢失     | Web点击“确认原快照接收结果”，沿用原请求；不要盲目新建第二份任务                           |
| 无账号或能力不足 | 打开已登录后台首页再刷新；记录页面阶段和提示文案，继续使用复制                            |
| 找不到唯一入口   | 记录“草稿箱/新的创作/图文”实际可见入口，等待适配器修正，不点保存/发布验证                 |
| 当前编辑器非空   | 停止覆盖；保留原文章，回到后台首页重新准备                                                |
| 执行中           | 等待；取消/清空被阻断                                                                     |
| 结果不确定       | 检查插件打开的后台标签与实际内容。检查后在“中断恢复与清理”勾选确认，明确丢弃，再从Web重送 |
| 存储损坏         | 先检查后台，再明确“清空损坏的任务存储”；不影响Web原稿                                     |
| 24小时到期       | 正常任务/回执清除。中断任务仅保留匿名阻断提示，检查后丢弃                                 |

丢弃/卸载插件不会撤销已创建的后台图文。用户自行处理后台残留。不要把插入读回当作保存成功。
