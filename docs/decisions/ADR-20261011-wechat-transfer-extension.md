# 保留 Web 编辑器并通过 Chrome 轻量插件传稿

## 背景与约束

维护者确认官方HTTP草稿API无法使用，选择Web加轻量Chrome插件。本轮只完成设计与实施计划；第一版自动进入草稿箱、新建图文、插入文字排版，由用户检查后手动保存。含图片文章明确提示使用既有复制流程，不截去图片继续插入。

现有纯前端Web、静态托管与本地数据可以继续承担写作和排版；普通网页受跨站访问边界限制，不能直接控制公众号编辑器。微信公开了登录编辑器页面上的MP编辑器JSAPI，但导航/新建和真实账号兼容还需现场验收。

## 已选择方案和依据

保留唯一Web写作工作台；Chrome MV3插件作为可选传稿连接器，提供打开Web/公众号、接收不可变快照、后台按钮、单任务状态与页面适配。插件不保存可继续编辑的原稿、配色或历史，不复制整套编辑器，不新增服务端或账号/云同步。

Web与扩展共享显式版本的运行时Schema，来源及项目路径校验，先保存快照再应答。写入由用户在插件界面明确启动并确认公众号目标；官方页面JSAPI优先，新建导航和标题通过独立页面适配器实现。结果不确定时停止，不重放新建或全文写入；“已插入”与“已保存”分开。

首版只操作本次新建的空图文编辑器，不覆盖已有文章，不自动保存、发布、群发或访问私有HTTP接口。图片能力被明确延后，现有Web复制与图片行为继续有效。插件独立构建和分发，Web依旧可不安装插件使用。

## 替代方案与影响

- 官方HTTP草稿API加服务端：维护者已排除，不保留为首版实施前提。
- 完整插件编辑器：多一套origin存储、写作入口、迁移/同步与发布成本，当前不采用。
- 油猴脚本：可用于自用验证，但本项目选择独立插件以管理任务、权限、通信和版本。
- Web/PWA手动复制：继续作为无插件或页面能力不足时的有效流程。

引入扩展意味着必须维护安装/版本、来源白名单、协议协商、页面适配和人工验收；公开接口不能承诺微信页面永远兼容。第一版功能边界和保守重试策略换取较小的数据所有权和维护范围。
