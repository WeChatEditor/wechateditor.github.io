# 保留 Web 编辑器并通过 Chrome 轻量插件传稿

## 背景与约束

维护者确认官方HTTP草稿API无法使用，选择Web加轻量Chrome插件；已实现独立工程与安装包，实际公众号仍待人类验收。点击Web发送后自动进入草稿箱、新建图文、插入文字排版，由用户检查后手动保存。含图片文章明确提示使用既有复制流程，不截去图片继续插入。

现有纯前端Web、静态托管与本地数据可以继续承担写作和排版；普通网页受跨站访问边界限制，不能直接控制公众号编辑器。微信公开了登录编辑器页面上的MP编辑器JSAPI，但导航/新建和真实账号兼容还需现场验收。

## 已选择方案和依据

2026-10-12维护者明确导航使用草稿箱、新的创作、文章，平台在新标签打开文章编辑器；插入必须绑定本次文章点击打开的唯一新标签及空正文。没有已打开后台时，打开固定首页识别已登录账号后继续；未登录则保留未启动任务，登录页面就绪后继续。该澄清保留独立新建、正文快照、官方接口及手动保存边界。

2026-10-12维护者进一步授权手动发送同时写入系统剪贴板，以及网页启动时一次检查插件连接。无载荷PING仅返回版本，不恢复发送状态查询；复制和插件提交独立反馈，缺失插件仍能复制并提示安装。发送点击同时授权本次复制和自动插入；自动保存仍只同步插件独立快照，不写系统剪贴板。浮层及抽屉的面板入口按连接可用性启用。该修订补充交互，不取代既有来源、文字传稿、独立新建和手动保存边界。

2026-10-12补充自动保存同步插件：Web本机自动保存成功后可发送SAVE_ARTICLE保留最新排版供插件面板复制；它不授权公众号页面写入。可复制快照与手动发送任务分开，自动更新不修改执行payload，也不启动任务或占发送回执。只有手动“发送到公众号”授权新建/插入，系统剪贴板以用户点击复制或发送触发。插件继续不持有可编辑原稿/配置/历史，文字和短期TTL边界保持。

2026-10-12继续明确：自动插入不保证成功，发送后优先打开后台尝试，插件面板提供本次文字排版的手动复制退路。成功/失败/中断不立即删除当前快照，在24小时TTL或下次发送时删除/替换；正文读取仅开放给可信插件面板，不引入编辑器、文章历史或发送状态检测。

2026-10-12维护者修订交互：Web点击发送本身即为本次自动新建和插入的授权，不再另行勾选或点击启动。插件已选有效账号优先，首次默认第一个可用账号；公开发送状态查询和取消/恢复/清理交互删除。内部去重、账号复核、独立空编辑器和中断不自动重放继续作为写入边界。详细现行行为以插件设计和[交互简化计划](../plans/active/2026-10-12-wechat-transfer-simplification.md)为准。

保留唯一Web写作工作台；Chrome MV3插件作为可选传稿连接器，提供打开Web/公众号、接收不可变快照、公众号选择与自动页面适配。插件不保存可继续编辑的原稿、配色或历史，不复制整套编辑器，不新增服务端或账号/云同步。

Web与扩展共享显式版本的运行时Schema，来源及项目路径校验，先保存快照再应答。Web点击发送即授权本次写入；使用已选有效账号或默认第一个可用公众号，没有额外启动或勾选确认。官方页面JSAPI优先，新建导航和标题通过独立页面适配器实现。结果不确定时停止，不自动重放新建或全文写入；“已插入”与“已保存”分开，不提供发送状态检测。

首版只操作本次新建的空图文编辑器，不覆盖已有文章，不自动保存、发布、群发或访问私有HTTP接口。图片能力被明确延后，现有Web复制与图片行为继续有效。插件独立构建和分发，Web依旧可不安装插件使用。

## 替代方案与影响

- 官方HTTP草稿API加服务端：维护者已排除，不保留为首版实施前提。
- 完整插件编辑器：多一套origin存储、写作入口、迁移/同步与发布成本，当前不采用。
- 油猴脚本：可用于自用验证，但本项目选择独立插件以管理任务、权限、通信和版本。
- Web/PWA手动复制：继续作为无插件或页面能力不足时的有效流程。

引入扩展意味着必须维护安装/版本、来源白名单、协议协商、页面适配和人工验收；公开接口不能承诺微信页面永远兼容。第一版功能边界和保守重试策略换取较小的数据所有权和维护范围。
