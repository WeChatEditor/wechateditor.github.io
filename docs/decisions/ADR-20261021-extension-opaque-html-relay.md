# 插件作为不解释排版规则的HTML转发器

## 背景与约束

维护者明确要求删除插件格式校验，避免网页样式更新反复要求发布插件，并审查其他升级耦合。0.1.14将HTML/CSS规则编译到worker与popup，且以版本号强制同步；固定profile、标题64字及读回标签计数也参与内容限制。

## 已选择方案和依据

格式、媒体、字体和平台建议仅在Web预览/导出/提交前检查；通过共享包独立content公共入口提供。基础消息入口只含传输Schema、来源、体积、摘要和固定操作，不依赖内容解析器，插件不加载Web校验代码。

插件0.1.15删除接收、复制及写入读回中的格式/媒体/标签白名单。读回保留账号、标题和规范化文字一致性及用户活动检查，不承诺排版保真。profile为有界不透明字符串，传输标题不固化64字；Web保留当前标题规则，插件只遵循页面实际标题控件限制及写入同步结果。

PING声明稳定html-relay@1能力，Web按能力识别，而非每次排版规则的版本号。旧插件缺少此能力时明确提示升级，此次仍需一次安装更新；今后普通样式和已有字段内的输出变化仅更新Web。协议版本2、严格消息字段、摘要算法和持久化结构保持，实质传输协议变化仍需协调升级。

## 替代方案与影响

不保留可选或远程下载的插件格式校验，不把第三方代码或任意动作交给Web。来源、消息字段/体积/摘要、账号、空文章、本次新建、用户活动与禁止重放等操作保护继续存在。插件只把可信Web的HTML交给官方编辑器/剪贴板；Web承担输出清洗与排版限制。

## 适用边界、替代来源和验证

本决定细化既有Web加轻量插件路线，不改变自动新建和人工保存。微信页面选择器/接口变化、域名/扩展ID/权限变化、传输/存储协议和图片上传等原生能力仍可能要求插件更新；审计矩阵见[设计](../design/extension-update-boundaries.md)。工程检查、契约/治理及包输入隔离验证不代替公众号人工验收。
