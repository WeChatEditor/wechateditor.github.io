# 桀士排版采用独立纯前端应用

原决策在Cyber-Sight确认于2026-10-04，本次迁入独立工程；[固定来源](https://github.com/tanghaojie/Cyber-Sight/blob/2e48a6c8b37a60c9bda704d6c3fefa4ce4fd7ef4/docs/platform/decisions/ADR-20261004-jlab-wechat-editor-standalone-app.md)。以下过去日期、提交与验收状态仅指来源，目标技术/人工证据见[迁移计划](../plans/active/2026-10-08-jlab-independent-migration.md)。当前交付位置为本仓库apps/frontend，治理不再继承来源所有权；原纯前端、桌面与存储语义继续有效，历史界面尺寸以[当前UI设计](../design/jlab-wechat-editor-ui.md)为准。

## 背景

微排技术调研曾提出在现有 frontend 中注册公众号编辑模块。维护者明确选择 monorepo 中独立应用，并确认产品名称、技术栈、纯前端范围与交互裁剪。本 ADR 记录已确认约束；应用已在提交 `5fc0bd1` 实现，桌面交互与公众号粘贴仍待人工验收。

## 决策驱动因素

- 排版工作台需要独立启动、构建和静态部署。
- 本地 Markdown 编辑、主题、结尾与剪贴板流程不需要服务端。
- 复用团队熟悉的技术栈，保留单页工作流。
- 收敛原站功能与工具栏复杂度，设置修改时保持预览可见。

## 考虑的方案

1. 在 apps/frontend 注册菜单和页面模块：原研究建议，未实施，现不采用。
2. 在 apps 中建立独立纯前端应用：维护者选择。

## 决策

- 产品为“桀士排版·公众号助手”，英文“JLab WeChat Editor”。
- 在 `apps/frontend/` 独立交付；不接入现有 frontend 菜单、路由、认证和 AdminLayout。
- Vue 3、Pinia、Element Plus、Vite、TypeScript，单一页面，无 Vue Router、后端或 HTTP 业务 API。
- 内部按业务职责与组件组织，应用入口只组装；不创建对应空 backend/contracts 目录。
- 排除新手教程、文章包导入、全部 IP 功能。
- 顶部合并成一层，默认直接展开正文色、局部字色；章节样式改为抽屉按钮，文字设置整合字号/间距/字体，与配色、固定结尾平行。
- 高级配置用左侧覆盖式 Element Plus Drawer，不挤压工作区，修改实时预览；主工作区保留 Markdown/预览双栏并允许拖拽比例。
- 2026-10-05 维护者进一步要求：移除插图和下载；导入移到原稿标题右侧；预览标题右侧使用手机/电脑 radio 和专注按钮；章节使用滚动列表选择；分栏仅保留无占位拖拽图标。本 ADR 与现行设计同步此次授权调整。
- 本 ADR 初次确认时只调整设计与方案；2026-10-05 维护者授权实施，并明确仅做横屏桌面工作台，现行实现状态见关联设计。
- 2026-10-05维护者批准V2完整改造并要求电脑阅读也有外壳：保留左侧覆盖抽屉，52px顶栏、320px抽屉、可视化样式卡片和来源映射气泡；阅读外壳不进入文章或导出。细节见[工作台UI设计](../reference/source-designs/jlab-wechat-editor-ui.md)。

2026-10-06人工验收调整：配色与固定结尾抽屉最大520px，其他最大320px；章节序号独立控制，配色管理沿用现有本地配置；完整手机/电脑外壳内滚动。独立应用、无后端和导出边界不变，现行细节以工作台UI设计为准。

## 正面结果

应用依赖与交付边界清晰，本地能力不依赖后台启动；设置与预览保持同一工作流，现有管理应用无需新增排版菜单。

## 负面结果与风险

独立应用需维护自己的构建入口与静态部署配置；所有权清单和检查覆盖需在实施前接入。纯前端无法保证云备份或服务端图床，浏览器本地数据与公众号复制仍需要失败处理和人工验收。

## 验证和复审条件

独立应用不得导入管理 frontend 私有代码或要求后台运行；排除功能不应出现在 UI 与数据模型中。未来若需要云存储、公众号 API、账号、嵌入管理系统或其他发布渠道，应重新评审，而不是沿用本 ADR 自动扩展。
