# 公众号排版结构兼容修复

## 目标与当前证据

维护者反馈传稿后副标题字重、无序和有序列表、表格居中、代码窗口按钮及总结列表间距六项问题，并明确要求直接检查页面、修复后复查。已读取线上编辑器的当前原稿和预览DOM：标题只在外层声明bold；普通列表依赖ul/ol默认marker；总结行依赖flex/gap；代码三点为空span且取主题色；表格margin为20px 0。上述结构是兼容隐患，不能据此宣称已确定微信的转换行为。

公众号后台被浏览器站点安全策略拒绝，禁止绕过。修复与本地/编辑器实际浏览器检查可以继续；公众号插入、保存重开和手机明暗效果仍需维护者验收。保留当前原稿、IndexedDB current和配置，不以测试内容覆盖线上草稿。

维护者随后提供五张左右对照截图：平台侧出现空列表标记、强调与正文拆行、1/3/5空号、代码换行折叠和圆点消失、总结大间距，副标题变细且正文呈现更粗。截图是实际接收效果证据；无法据此读取平台DOM或断言具体转换源码。进一步为所有映射文字写入明确的最终字重，普通文字400、强调/标题按其最近排版上下文保留，避免目标编辑器选区粗体状态影响继承。代码换行改为br，空格/制表符使用有实际内容的不换行空白span保留，纯文字按内部标记恢复原始空格/制表符。不能继续只依赖pre的原始换行。

## 实现、边界和数据流

typesetting新增私有结构整理文件，由styleArticle在基础排版和卡片样式之后调用。仍由articleDom统一服务预览、富文本复制和插件文字快照；不新增外部CSS、媒体、权限、存储字段或模块依赖，插件仍为HTML转发器。

- 标题正文增加语义strong并将字重/字号/行高显式传给文字span；章节编号等装饰保留自身字重，章节样式和卡片标题仍控制最终字重。
- ul/ol/li在最终共享DOM转换为section/p和可见marker，使用普通块布局及悬挂缩进。嵌套缩进、非1起始编号、多段列表、强调和源行/文字映射保留，不依赖原生列表marker或flex。标记是装饰，纯文字输出先恢复其对应文字，再删除其他装饰，不重复编号。
- 总结直接列表使用同一转换，保留勾选/序号徽章；行距至多1.65、条目间距6px、内边距8px 10px，列表内部段落不叠加全文paragraphGap。嵌套列表仍使用普通层级样式。
- 表格外层显式居中，table以auto左右外距定位；单元格正文用零外距段落显式继承列对齐，保留Markdown指定的左/中/右，无指定时居中。
- 代码窗口把工具栏放在pre外，三个红黄绿圆点使用非空可见字符和内联颜色；代码正文保留原始空格/换行与主题配色，工具栏不进入纯文字，指定语言时显示语言标签。

wechat-export的readableText识别上述marker，其他清洗和安全边界保持；无需修改传输协议或重新发布插件。

## 验证与验收

执行格式、Lint、类型、生产构建、模块/文档、治理/共享契约和归档CI。维护者本次明确要求查看网页并复查，允许通过浏览器检查实际预览与复制结果；不引入前端测试框架。检查默认文章、混合嵌套、长条目、非1编号、多段条目、总结、命名/无名代码及Markdown表格对齐。不能把编辑器或本地检查标为公众号验收。关联[实施计划](../plans/active/2026-10-21-wechat-layout-compatibility.md)。
