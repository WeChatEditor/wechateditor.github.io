# Markdown 封面与总结卡片

2026-10-21[排版兼容修复](wechat-layout-compatibility.md)将总结直接列表改为显式徽章和section/p块布局，去掉flex/gap依赖，内边距8px×10px、条距6px、行距至多1.65，列表段落底距至多6px。嵌套列表、原序号和文本映射保留；纯文字由显式marker还原对应圆点/编号。此段取代原先独立flex列表行的实现描述。

2026-10-21按[微信内容规范](wechat-content-rules.md)§4.1.2将总结卡渐变改为主题纯色，避免文字背景在Dark Mode转换时失去预期。封面阴影与列表样式保留，Web输出安全集合允许这些已生成样式及浏览器border-image:none序列化；插件不重复校验，不能把项目旧白名单误称为微信支持限制。

## 语法和范围

采用[Callout 决策](../decisions/ADR-20261019-markdown-cards.md)。仅识别顶层引用块的第一段：`> [!hero] 刊头小字` 或 `> [!summary] 总结标题`，类型不区分大小写。标记段与后续正文用引用空行分开。hero 必须含直接子级 H1，summary 必须含直接子级有序或无序列表；缺少结构、未知类型、嵌套卡片标记按普通引用保留，不丢弃内容。代码围栏和行内代码不识别为卡片。

hero 第一段为可选眉题，首个 H1 为主标题，其他 Markdown 为内容；summary 第一段为可选标题，列表为要点。普通强调、链接、长段落、嵌套列表和引用继续交给原解析器。卡片不新增任务状态、交互复选框或原始 HTML 权限。

## 职责与数据流

article 在 markdown-it block 之后、inline 之前将合法引用 tokens 标记为受控 section，去除类型标记，保留 Markdown 子节点、源行和可见文本位置映射；实现留在 article 私有文件，不扩展公共文件或模块依赖。typesetting 在基础排版后应用内联卡片样式：hero 为带刊头与可选品牌落款的分层卡片，summary 为浅底和独立条目。卡片标题不参与章节最小级别计算、装饰或编号。

预览、富文本复制和插件文字快照继续使用同一个 articleDom/styleArticle。卡片仅生成现有白名单允许的 section/p/span/标题/列表等节点，不使用 SVG、伪元素、外部 CSS 或图片。类型和源映射属性只供预览排版，导出仍剔除；装饰符号和对勾用 data-decoration 标记，不计入原稿文字位置或纯文字导出。

## 设置与入口

标题样式抽屉增加卡片设置：刊头符号（星芒、菱形、无）及品牌落款（0至40字符，留空隐藏）。属于 typesetting 配置，与字号和配色同存 localStorage，无配置历史；读取缺失补默认，错误类型或非法枚举拒绝，不覆盖原记录。文章、current、版本格式与所有权不变。

原稿工具栏增加“封面卡”“总结卡”，支持无选区插入模板及将完整选中行转换为卡片，沿用 IME、禁用、长度限制与原生撤销路径，不使用 modal。默认文章开头展示封面卡，结尾展示总结卡，正文串联简短Markdown示例，并说明工具栏入口及两种标记；不保留各国语言和各编程语言教程。只有没有 current 时加载，新代码不替换已有或空草稿。

## 失败与验收

原始 HTML 仍禁用，品牌用 textContent 插入。嵌套列表只为卡片直接列表增加装饰，避免重复打勾；长标题和链接换行，颜色前景按对比度回退。基础 Markdown 和当前主题设置保持。

工程执行格式、Lint、类型、生产构建、模块/文档、治理与契约检查；不新增或运行前端测试、浏览器自动化。人类验收默认开场、插入/选区/IME/撤销、18套配色、长内容/嵌套结构、源行同步与局部标注、旧配置恢复及公众号粘贴/保存。实施状态见[计划](../plans/active/2026-10-19-markdown-cards.md)。
