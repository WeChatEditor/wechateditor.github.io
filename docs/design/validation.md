# 验证策略与证据边界

三种预设分别在干净目录用冻结锁文件安装，执行格式、Lint、类型、模块、文档结构、生产构建和治理测试。全栈契约先构建，测试实际 dist 导出；后端测试 Nest/Fastify 的实际注入响应及关闭，另有真实进程监听/关闭检查。

治理测试使用临时文件/Git 仓库覆盖合法和非法依赖、提交格式、文档损坏、归档状态、阈值、即时触发及初始化生命周期。这不是前端功能自动化。前端不执行单元、组件、E2E 或浏览器测试；空启动页面及全栈加载/成功/失败由人类验收。

本地与 CI 使用相同入口。技术检查只证明对应层，不证明浏览器交互、部署或 npm 发布。Windows 和 Linux 的运行证据分别登记；若没有 Linux 环境，只提供 Linux CI 并明确未实际运行。

新增测试仅覆盖行为和失败模式，机械排版无需镜像测试。验证失败先修复，再记录实际结果；不为满足提交步骤隐瞒未完成人类验收。
