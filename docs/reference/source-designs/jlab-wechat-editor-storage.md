# 桀士排版数据存储与文章版本

维护者确认：所有配置、固定结尾修改后实时保存到 localStorage，不保存历史或版本；文章 Markdown 保存到 IndexedDB，默认覆盖 current，仅用户主动新增版本时按时间戳保存。

## 数据所有权和公共边界

workspace 负责存储编排，沿用 workspace.store.ts、draft-storage.port.ts、workspace.page.vue 公共入口；仓储适配、校验和历史面板均为模块私有。其他五模块保持现有公共接口，无后端或新依赖。

| 数据                                                                   | 位置                                                  | 更新规则                                       |
| ---------------------------------------------------------------------- | ----------------------------------------------------- | ---------------------------------------------- |
| 配色、章节、字体间距、固定结尾、分栏比例、预览模式、局部颜色选择器偏好 | localStorage `jlab-wechat-editor:settings`            | 同步覆盖唯一配置记录；无历史                   |
| Markdown、正文标注、文章元信息及旧素材 Blob                            | IndexedDB `jlab-wechat-editor` / `drafts` / `current` | 450ms 防抖串行覆盖，事务完成才显示成功         |
| 文章版本                                                               | 同库 `versions`，毫秒时间戳数字键                     | 点击新增版本时保存不可变文章快照；无配置与结尾 |
| 抽屉、选区、专注、复制结果和历史预览                                   | 内存                                                  | 刷新后不恢复                                   |

IndexedDB 升级到数据库版本 2；current 数据格式 schemaVersion 2，新增 writeId 用于事务内乐观并发校验。历史记录包含 timestamp 和文章数据格式 2，保存时同时写入 current。同毫秒或系统时钟回退时取已有最大时间戳加一，使用 add 避免覆盖旧版本。历史按时间戳倒序列出，日期显示使用用户浏览器本地时区和毫秒。

## 读写和失败路径

启动先读取并校验配置，再读取 current。旧格式 1 的完整草稿由兼容校验读取：仅当 localStorage 配置不存在时迁出旧配置；配置写入成功后，将文章和素材转换为格式 2，原位覆盖 current。已有配置优先。不自动创建历史版本。配置写入失败时保留旧 current，显示迁移失败，不进行部分覆盖；未知版本和损坏记录暂停对应自动保存，保留原数据。

配置修改同步写入 localStorage，无防抖；写失败保留内存编辑并显示失败，可重试。正文改变仅保存文章，不写配置；配置改变不写 current 或历史。两个存储不宣称跨库原子事务。当前文章保存、新增版本、恢复、删除串行编排；文章事务检查读取时的 writeId，发生其他页面写入时拒绝覆盖并暂停。配置通过 storage 事件检测其他页面更新并暂停本页配置写入，提示刷新；文章通知沿用 BroadcastChannel，同时 writeId 检查不依赖通知可用性。

历史面板支持新增版本、只读查看 Markdown、恢复和删除。恢复/删除前提示确认；恢复替换 current 的正文、标注和旧素材，继续使用当前排版与结尾，不修改或创建历史。恢复成功以 current 事务完成为准；恢复期间禁止正文编辑，失败保留原内存文章。删除不修改 current。列表读取失败独立提示，不把失败当成空历史。加载和读写期间禁用相关操作；版本读取校验失败保留记录。关闭页面补保存仍是尽力操作，不能保证浏览器终止前异步事务完成。

## 验证边界

执行应用模块边界、TypeScript、生产构建、ESLint、仓库格式与归档 CI 检查。依仓库规则不新增或运行前端自动化/浏览器测试。维护者手工验证：配置即时持久化、正文 current 覆盖、主动版本与同毫秒冲突、查看/恢复/删除、刷新、旧草稿迁移、存储权限/配额/损坏、两页面冲突及恢复时选区失效。实际检查结果记录在实施计划和 AI 日志。

2026-10-06配置扩展：config新增chapterNumberEnabled和palettes（id、name、colors、custom）；旧记录缺少字段时补齐默认值，保留实际文章颜色。配色名称1至30字符，id唯一，所有配色总计1至9组，五个颜色角色分别校验。损坏的新字段不被默认值覆盖，仍暂停保存。配色库与章节开关随配置同步覆盖，不写文章历史。
