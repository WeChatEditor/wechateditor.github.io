# 桀士排版·公众号助手

## 1. 产品定位与本轮状态

中文全名为 **桀士排版·公众号助手**，顶栏标题为“桀士排版”、副标题为“公众号助手”，不展示英文应用名。它是在 Cyber-Sight monorepo 中独立交付的纯前端应用，路径为 `apps/wechat-editor/`，workspace 名为 `@jlab/wechat-editor`。

应用目录和包名已选定。2026-10-05 维护者授权开始实施，并明确仅支持横屏桌面网页，不做窄屏和手机工作台适配。`accepted` 表示产品方案约束已确认，公众号接收效果仍需人工验收。

沿用 Vue 3、Pinia、Element Plus、Vite、TypeScript。只有一个工作台页面，不引入 Vue Router；无后端、HTTP 业务 API、数据库服务器、账号或权限依赖。单独开发、构建和静态部署，不注册到 `apps/frontend` 的菜单、路由、AdminLayout 或页面模块。

## 2. 范围

| 能力                | 当前方案                                                            |
| ------------------- | ------------------------------------------------------------------- |
| Markdown 编辑与预览 | 保留左侧源文本、右侧公众号预览，实时渲染                            |
| 导入                | 保留单个 `.md`/`.txt` 文件；不接收文章文件夹、压缩包或文章包        |
| 基础排版            | 正文色、局部字色、章节样式直接可用                                  |
| 文字设置            | 字号、间距、字体集中在一个抽屉                                      |
| 配色                | 预设配色与元素颜色角色调整，不含 IP 上传/提色                       |
| 固定结尾            | 独立 Markdown、启停、本地保存，追加到预览和复制内容                 |
| 本地保存            | 文章、排版、局部标注、结尾和必要本地素材可恢复                      |
| 公众号复制          | 受控 HTML 与纯文字共同写入剪贴板，保留兼容诊断                      |
| 工作区              | 可拖拽双栏比例；保留专注预览和手机/电脑预览宽度切换                 |
| 不纳入              | 新手教程、文章包导入、IP 形象/去底/提色/配色推荐/保存               |
| 不属于当前路线      | 云草稿、公众号 API、账号系统、服务端图片托管、AI 排版和其他发布渠道 |

原站能力和算法只作研究依据，见[微排技术调研](../wechat-editor-research.md)。数学公式、Mermaid、图表和复杂 SVG 没有进入已确认功能；基础 Markdown 的代码块和表格属于当前排版范围，需要真实公众号验收。

## 3. 单层工具栏与主工作区

2026-10-05维护者批准完整UI改造，并追加电脑阅读外壳；实现提交`87f1f9ebf7463c432da20d3747e0128fd70438bb`，交付于2026-10-06。现行细节见[工作台UI与阅读交互](jlab-wechat-editor-ui.md)：52px顶栏、统一应用tokens、可视化卡片、选区气泡、Markdown快捷格式、稳定诊断和输出质感。原有配置保持兼容，新草稿默认为清透蓝与便签引用底色。

合并原站的两层标题栏为一个工作台顶栏。默认直接展开的排版控件只有“正文色”“局部字色”；“文字设置”“配色”“固定结尾”以平行按钮呈现，点开抽屉后才显示具体选项。章节样式改为抽屉按钮，复制保留顶栏；导入放到原稿标题右侧，手机/电脑宽度 radio 与专注预览放到预览标题右侧。移除插图和 Markdown 下载按钮及命令，备份提示改为手动复制原稿。

```text
┌ 桀士排版 ─ 正文色 ─ 局部字色 ─ 章节样式 ─ 文字设置 ─ 配色 ─ 固定结尾 ─ 复制 ┐
├───────────────────────────────────────────────────────────────────────────────────────────────┤
│ 左侧覆盖抽屉（不挤压主页面） │ Markdown 源文本 │ 可拖拽分隔线 │ 文章实时预览                    │
└───────────────────────────────────────────────────────────────────────────────────────────────┘
```

品牌短名使用“桀士排版”，完整产品名用于说明及发布元信息。浏览器标题按维护者手动确认使用“桀士排版·公众号助手”。工具栏保持单层，工作台仅面向横屏桌面；不增加窄屏断点和手机布局。

正文色修改普通正文的默认颜色，不覆写显式局部标注。局部字色作用于预览中的有效选中文字；章节样式作用于章节标题的视觉表达，保持 Markdown 原有标题层级和内容。

## 4. 左侧抽屉交互

文字设置、配色、固定结尾、章节样式和历史版本使用Element Plus Drawer从左侧覆盖展开，不占工作区宽度、不改变两栏比例。无遮罩且不锁页面滚动，顶栏保持可点击，支持关闭按钮与Escape。配色、结尾、章节样式与历史版本抽屉宽度最大520px，文字设置抽屉最大320px，位于52px顶栏下方至状态栏上方，覆盖原稿区域。章节使用与输出相同规则的九种真实预览卡片；历史支持主动新增、查看、恢复和删除。

| 抽屉     | 内容                                                         | 生效方式                                    |
| -------- | ------------------------------------------------------------ | ------------------------------------------- |
| 章节样式 | 独立序号开关与九种真实章节预览卡片                           | 点击即时选择，选中态即时保存到 localStorage |
| 文字设置 | 字号、行距/段距等间距、字体                                  | 修改即更新排版模型与预览                    |
| 配色     | 初始化六组、总计1至9组的可编辑配色卡片、颜色角色、对比度提示 | 修改即更新主题，不改变 Markdown             |
| 固定结尾 | 开关、Markdown 编辑、清空                                    | 启用时实时追加一次；不写回正文 Markdown     |

一次只打开一个抽屉。再次点击当前按钮关闭；点击其他按钮在同一面板切换内容。关闭、切换与重新打开保留已生效设置，不设“确认/取消”提交步骤。需要清空或重置时用明确动作，不通过关闭面板隐式丢弃设置。

默认关闭抽屉；配色、结尾、章节样式与历史版本最大520px，可覆盖部分预览；文字设置面板最大320px，编辑栏拖窄时钳制到该栏宽度。抽屉开关不触发全文重新载入或重置局部标注。

字号和间距沿用原站可调参数作为初始参考，默认字号 16px、行高 1.9，具体选项在实施前核对并写入配置。默认字体选“公众号默认”，预览继承适当字体栈，导出不设置自定义 `font-family`。若提供思源黑体/微软雅黑等显式选择，应同步用于预览与导出，并提示设备相关的显示差异；不能选择后在复制时静默丢弃。它们属于兼容扩展，不能保证设备安装或微信保真。

颜色、字号、间距都通过文章配置影响预览；应用控件与文章主题独立。默认提供暖金、青绿、墨色、清透蓝、复古潮流、活力橙六组配色，所有配色支持弹窗改名、更新颜色与删除，操作按钮在hover或键盘聚焦时显示，总计1至9组；可重置为默认六组。不依赖管理系统PRISM壳，也不把应用主题视为微信深色算法。

## 5. 双栏拖拽与空间约束

原稿 textarea 与排版预览在受限的网格行内独立滚动，标题栏与底部状态栏固定保留。网格行使用 `minmax(0, 1fr)`，网格项及内部 flex 内容设置 `min-height: 0`，避免长文撑大工作区后被裁切。底部左侧统一显示排版文字的非空白字符数与预计阅读时长（包含启用的固定结尾，按每分钟 600 字向上取整，空文为 0 分钟）；右侧显示“数据仅保存在当前浏览器”与产品信息。

两栏滚动条使用浏览器thin宽度，旧WebKit回退为6px；轨道透明，滑块为低对比中性灰色，悬停内容区时略加深。样式仅限原稿textarea和预览滚动区，不进入文章导出。

保存状态集中于顶栏，显示自动保存、等待、写入中、成功及失败/暂停状态；长状态保留完整 title。正文使用 450ms 防抖、串行 IndexedDB 保存与离开页面时补保存；配置和固定结尾同步写入 localStorage，无防抖。底部和结尾不设手动保存按钮；失败时顶栏提供重试，历史面板另有主动新增版本入口。

主功能区保留 Markdown 在左、预览在右。建议默认比例 50:50；分隔手柄拖拽改变两栏在完整工作区中的比例，抽屉开关不参与比例计算。

建议桌面两栏最低宽度：编辑栏 280px、预览栏 320px；拖拽根据容器宽度与两栏最低值动态限制，不能简单固定为 30%–70%。两栏仅保留 1px 边界；拖拽图标绝对定位在边界中央，12px 宽操作区域，不预留网格列或整列面板。比例可作为应用偏好保存；容器变窄时只钳制实际显示，不改掉用户原先偏好，空间恢复后重新应用。

鼠标与触摸共享比例模型，处理指针捕获、释放、取消与失焦清理；只在手柄处抑制文本选择/触摸默认行为。手柄可键盘聚焦，用左右方向键调整，提供 separator 语义、当前比例和边界。专注预览临时隐藏编辑栏与手柄，退出后恢复原比例；它是页面状态，不是新路由。

工作台固定最小宽度800px，配色、结尾、章节样式与历史版本抽屉宽度最大520px，文字设置抽屉最大320px，以800×720、1280×720和1440×900为人工验收基线。小于800px允许页面横向滚动，继续保留桌面双栏，不实现手机布局。顶栏保持52px单层，控件不足时仅顶栏内部横向滚动。

手机/电脑预览切换改变文章阅读宽度模拟，不改变应用布局和输出。两者均有可关闭的阅读外壳；模拟公众号/原创信息在文章根外，不可标注、不持久化、不复制。画板自适应，不显示尺寸提示，不强迫应用超过最低尺寸，不替代真实公众号验收。

## 6. 应用与内部职责

独立应用是交付单元。内部能力按组件和职责组织，遵守仓库的 Foundation/Platform 所有权规则，不把新产品注册成现有 frontend 的一个模块。

```text
apps/wechat-editor/
  package.json / index.html / vite.config.ts / tsconfig*.json
  src/
    main.ts / App.vue                 单页面组装与初始化
    platform/
      app.config.ts                   应用名称、存储命名空间、默认值
      modules/
        workspace/                    单层工具栏、抽屉宿主、分栏、Pinia 与本地持久化
        article/                      原文输入、Markdown 解析、预览、选区映射
        typesetting/                  字体间距、颜色角色、章节样式与设置组件
        ending/                       固定结尾模型、编辑面板与追加规则
      assets/                       单个图片文件/远程图引用、尺寸和本地素材处理
        wechat-export/                微信兼容结构、内联、素材转换与剪贴板
```

应用已按上述六类模块创建，组件置于其能力目录，仓储适配位于 workspace/adapters。Vue 组件负责展示与事件，解析、标注迁移、主题规则、素材处理和导出规则留在与 Vue 解耦的具名服务中。

### 公共文件

| 能力          | 公共文件职责                                                                     | 依赖与边界                                   |
| ------------- | -------------------------------------------------------------------------------- | -------------------------------------------- |
| article       | `article.model.ts`、`article.service.ts`：文档模型、解析结果、位置映射和标注命令 | 不依赖工作台或其 store                       |
| typesetting   | `typesetting.model.ts`、`typesetting.service.ts`：配置、预设、颜色/章节计算      | 接受显式文章结构，不读取其他模块私有状态     |
| ending        | `ending.model.ts`、`ending.service.ts`：结尾配置与渲染                           | 可依赖 article 的公开解析能力                |
| assets        | `assets.model.ts`、`assets.service.ts`：素材准备、Blob/URL 与生命周期            | 浏览器文件和 Canvas 适配在内部，不上传服务端 |
| wechat-export | `wechat-export.model.ts`、`wechat-export.service.ts`：版本化输出及复制           | 接收只读快照，通过公共模型/端口协作          |
| workspace     | `workspace.store.ts`、`draft-storage.port.ts`：应用状态、命令与持久化端口        | 组装上列能力；拥有完整草稿的本地仓储         |

上表服务和模型均已实现。Vue 呈现入口和完整符号职责登记见 [内部模块边界](wechat-editor.md)。禁止 barrel，跨能力仅依赖登记公共文件；纯业务服务不能反向依赖 workspace。配置组件以 props/events 对接宿主。

```mermaid
flowchart TB
  UI[单页面工作台与抽屉组件] --> WS[workspace Pinia 与命令编排]
  WS --> A[article 原文/结构/标注]
  WS --> T[typesetting 排版配置]
  WS --> E[ending 固定结尾]
  WS --> S[assets 素材准备]
  WS --> X[wechat-export 输出]
  WS --> DB[浏览器草稿仓储 IndexedDB/localStorage]
  E --> A
  X --> A
  X --> T
  X --> E
  X --> S
```

不依赖 `apps/frontend` 的组件、状态、路由或认证；不创建 backend、api-contract 或服务端迁移。必要 Markdown/HTML 清洗依赖在实施时确认版本和许可、写入新应用 package；现有技术栈不意味着已经提供 Markdown 解析器。UI 默认采用 Element Plus 与应用样式，不增设其他 UI 框架。

## 7. 数据模型、选区与本地恢复

| 数据                | 内容                                                             | 持久化                                        |
| ------------------- | ---------------------------------------------------------------- | --------------------------------------------- |
| ArticleDocument     | schemaVersion、id、Markdown、revision、updatedAt、标注、素材引用 | IndexedDB                                     |
| TypesettingConfig   | 配色预设/具体角色、正文色、章节样式、字号/间距/字体              | localStorage 即时覆盖，无历史                 |
| Annotation          | 标注 id、原文/渲染位置映射、revision、颜色、失效状态             | 随草稿保存                                    |
| FixedEnding         | Markdown、enabled                                                | localStorage 即时覆盖，无历史；复制时纳入输出 |
| PreparedAsset       | 稳定 assetId、Blob/受控远程 URL、mime、真实尺寸                  | 本地 Blob 与引用存储，不保存临时 object URL   |
| WorkspacePreference | 两栏期望比例、预览宽度模式、局部颜色选择器偏好                   | localStorage 应用专属配置键                   |
| UiState             | 打开的抽屉、焦点、临时 Range、拖拽、复制状态                     | 不写入文章草稿                                |

存储命名空间为 `jlab-wechat-editor`，不复用微排或管理系统键。配置和固定结尾即时覆盖 localStorage，无历史和版本；文章、标注和必要 Blob 保存到 IndexedDB 的 current，450ms 防抖串行覆盖。用户主动新增版本时，以毫秒时间戳另存文章快照，不纳入配置或固定结尾。历史支持查看、恢复和删除，恢复继续使用当前设置；旧完整草稿兼容迁移。未知版本/读取失败暂停对应保存并保留原记录，跨页面通过通知和事务内 writeId 检查冲突。浏览器存储仍可能因清理、隐私模式或配额丢失；文章保存成功来自事务完成。模型、迁移、一致性和失败流程见[存储与版本设计](jlab-wechat-editor-storage.md)。

### 局部字色

点击控件前保存预览正文内的有效选区锚点。正文默认色与局部标注分开存储，标注覆盖默认色；改变配色、字体、字号、章节样式或关闭抽屉不清除标注。

不要只对预览 DOM 调用 Range 包裹。用渲染来源映射把选区转换成可序列化的片段，跨加粗、链接或段落的选择拆为多个合法文本片段。代码、图片、装饰和非文章区域不作为普通正文改色目标；混合选区含不可处理内容时整次拒绝并提示重新选择，不静默部分改色。

修改 Markdown 后，能确定映射的标注随编辑迁移；被删除或对应关系不唯一的标注标为失效并提示，不猜测迁移到另一段文字。重叠标注按最近一次操作确定颜色，相邻同色片段合并，避免反复嵌套 span。刷新后重建标注，不能依赖失效的浏览器 Selection 或 Range。

### 素材边界

删除文章包导入并不意味着所有图片消失：仍可处理 Markdown 中远程图片。单文件导入的相对图片路径不会自动访问用户文件夹；缺失素材需显示状态。本地插图功能已按维护者要求移除；旧草稿 Blob 继续恢复，新图使用 Markdown HTTPS 引用或在公众号后台补图。无文件夹扫描、路径猜测、ZIP 解包或本地目录授权流程。

素材异步处理以 document revision 为基准；完成时核对版本，淘汰过期结果。替换/删除/关闭时释放 object URL，持久化以稳定 id/Blob 为准。

## 8. Markdown、主题与公众号输出

保留基础 Markdown、标题、引用、列表、代码、表格和图片。章标题按明确语法与受控规则计算，原站九种章节样式作为视觉复刻参考，不增加 AI 分类。原站对纯文字章节的启发式属于候选兼容规则，实施时需与明确 Markdown 标题的优先级一起登记。

预览和复制共用文章语义、配置与有效标注。固定结尾独立渲染，启用时在尾部追加一次；不参加正文自动编号，也不修改原文。预览 CSS 限定在文章容器，不影响 Element Plus 或工具栏。

```mermaid
flowchart LR
  M[原文与固定结尾] --> AST[受控语义结构/来源映射]
  AST --> P[排版配置与有效局部标注]
  P --> V[实时预览]
  P --> X[微信 profile 标签/属性/样式转换]
  X --> I[素材准备与必要降级]
  I --> C[内联/最终清洗/诊断]
  C --> CB[HTML + text/plain 剪贴板]
```

规则以[公众号兼容文档](../wechat-editor-wechat-compatibility.md)为来源，当前只实现手动复制链路。HTTP 草稿 API 内容与大小规则仅作研究参照，不进入本应用方案。

导出固定文章 revision、配置与结尾快照，等素材完成或生成明确失败诊断。复制按钮应表达处理中、成功和失败状态；失败不能静默只复制纯文字。普通文本保持可编辑，宽表/长代码/外链/字体/图片状态按 profile 明确处理，不能承诺复制即完成微信托管或最终色值保真。

原始 HTML 禁用并作为文本显示；结构来自 Markdown 解析，样式由受控配置代码生成，再经 DOMPurify 允许标签/属性清洗。输入样式不透传，URL 单独控制；禁止依靠微信清除脚本保护本地应用。建议独立 HTTPS origin 隔离管理系统登录与草稿，正式地址待部署时确定。

## 9. monorepo 接入与实施前置检查

当前 workspace 已包含 `apps/*`；新应用建立后会进入 workspace。根 `build` 为递归构建，应用声明 build 后需纳入验证；根 dev 显式筛选既有应用，新应用需独立 dev 命令，不为了启动排版工具同时启动后台。

`.forge-sync.yml` 已登记 `apps/wechat-editor/` 为 Platform 所有。现有架构检查只覆盖既有应用根；新应用另有 `pnpm --filter @jlab/wechat-editor architecture:check`，以 TypeScript AST 检查六个模块、公开文件与单向依赖，不修改 Forge 的共享检查器或 Foundation 文档。

不导入现有 frontend 的私有代码。开发端口 5174，生产预览 4174，base 为相对路径，dist 为静态产物。面向具备 IndexedDB、ResizeObserver、PointerEvent 和 ClipboardItem 的现代桌面 Chrome/Edge，未对每个浏览器版本进行运行验收。markdown-it 15.0.2（MIT）和 DOMPurify 3.4.16（Apache-2.0 或 MPL-2.0）已写入应用与锁文件；原有应用锁定依赖保持原值。

## 10. 分期方案与验收

2026-10-05 已授权实施，下列阶段的代码交付与实际技术验证见[已完成计划](https://github.com/tanghaojie/Cyber-Sight/blob/2e48a6c8b37a60c9bda704d6c3fefa4ce4fd7ef4/docs/platform/archive/plans/2026-10-05-jlab-wechat-editor.md)；公众号粘贴验收不由静态检查代替。实现提交为 `5fc0bd104ddac5e76e5a6dbf9c77625353b82ad3`。

| 阶段              | 内容                                                                                             | 验收条件                                             |
| ----------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| P0 接入与兼容准备 | 依赖/许可、应用所有权、静态部署、代表性样稿与输出 profile                                        | 最小样稿经人工粘贴/保存/手机明暗验收；环境可独立启动 |
| P1 独立工作台     | Vue/Pinia 单页、单层顶栏、编辑/预览、四类覆盖式左抽屉、拖拽分栏                                  | 抽屉不挤压工作区、实时修改、关闭保留、拖拽和键盘可用 |
| P2 排版与恢复     | 初始化六组、总计1至9组的配色与颜色角色、九种章节、字号间距字体、标注、固定结尾、单文件与本地草稿 | 改稿、换设置、刷新后状态可靠；素材/标注失败可识别    |
| P3 公众号闭环     | 内联、最终清洗、图片/长行/表格/外链处理、HTML+纯文复制、错误状态、专注与预览宽度                 | 完整写稿→预览→复制→公众号保存闭环与人工兼容记录      |

P0 可提前暴露兼容风险，但最终输出适配随 P1/P2 功能继续核验；不是仅凭一次样稿通过就放行所有高级效果。P3 是纯前端产品收尾，没有云端扩展阶段。

人工验收至少包含：单层顶栏范围、抽屉覆盖/切换/实时预览、比例恢复及最小宽度、中文输入法、跨片段选区、改稿后失效标注、固定结尾启停、单文件编码/缺图、存储失败和刷新恢复、长代码/宽表、复制权限及真机明暗。教程/文章包/IP 不应出现在 UI、持久化模型或验收清单。

实施阶段 AI 执行格式、Lint、TypeScript、生产构建、所有权与归档检查；按仓库规则不创建或运行前端单元、组件、E2E 或浏览器自动化测试。P0–P3 的代码已实现，人工功能与公众号兼容验收仍待维护者执行，技术检查不代替这些验收。清单见 [应用说明](https://github.com/tanghaojie/Cyber-Sight/blob/2e48a6c8b37a60c9bda704d6c3fefa4ce4fd7ef4/apps/wechat-editor/README.md)。
